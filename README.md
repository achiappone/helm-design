# Helm Design

Parametric CAD for a 12.3" glass-cockpit helm display housing, built for a boat
dash and printed in ASA. Geometry is **code**, not a saved model — every part is
generated by a script in `cad/`, so a dimension change re-derives everything
downstream and the build fails loudly when something no longer fits.

## Parts

| | |
|---|---|
| `cad/helm_housing.py` | front shell + rear cover (the main part) |
| `cad/helm_visor.py` | hinged sun visor on detent pivots |
| `cad/bail.py` | dash bail mount: base plate + two arms on the cover's trunnions |
| `cad/heatsink_shroud.py`, `cad/lp24_*.py` | fan shroud, connector shroud and clamp |
| `cad/render.py`, `assembly.py`, `exploded.py` | renders straight from the solids |
| `cad/export_mesh.py` | 3MF/STL for the slicer, already print-oriented |

## Build

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python cad/helm_housing.py     # shell + cover, writes cad/out/
.venv/bin/python cad/helm_visor.py       # reads housing.json
.venv/bin/python cad/heatsink_shroud.py  # reads housing.json, writes shroud.json
.venv/bin/python cad/bail.py             #   "
.venv/bin/python cad/export_mesh.py      # -> 3MF + STL
```

`cad/out/` is generated and gitignored — everything in it rebuilds in seconds.

### The asserts are the point

The scripts refuse to produce geometry that cannot be built. They check, among
other things, that nothing protrudes from the face that prints against the bed,
that the rear brim can actually hold a fastener *and* a seal, that the detent
crown produces discrete teeth rather than fusing into a smooth ring, and that no
cover feature crosses the gasket path. Several of those exist because the
corresponding bug had already shipped once.

Mating dimensions live in `cad/out/housing.json`; the visor and bracket read
them rather than keeping copies. That is deliberate — when they kept their own,
they drifted, and the parts could not have assembled.

## Printer dashboard

`cad/printer_dash.py` is a local dashboard for a Klipper/Moonraker printer —
live temperatures, progress, and the WebRTC camera.

```sh
python3 cad/printer_dash.py      # then open http://localhost:8770
```

Point it at your printer with `PRINTER_HOST=10.0.0.42 python3 cad/printer_dash.py`,
or edit the default at the top of the file.

**It has to run locally, and it cannot be hosted on GitHub Pages.** Two reasons,
neither of them fixable from the page: the printer lives on a private LAN address
that nothing outside the network can route to, and Pages is HTTPS-only while the
printer speaks plain HTTP — browsers block that combination unconditionally.
Moonraker also sends no CORS headers here, which is why the script proxies it.

The proxy is **read-only by whitelist**: three status endpoints, GET only. It
cannot set a temperature, move the toolhead, or start, pause or cancel a job.
That is on purpose. Moonraker has no authentication by default, so if you ever
want this reachable from outside your house, put it behind a VPN — Tailscale is
the easy answer — and never expose the port directly.

## Docs

`docs/` is published with GitHub Pages: the current revision's drawings,
dimensions and verification results. Static and self-contained, so it works fine
there — unlike the dashboard.
